1. O que é o projeto

O Invest Advisor é um assistente que responde perguntas sobre regulação de investimentos no Brasil (normas da CVM — Comissão de Valores Mobiliários) usando apenas documentos oficiais como fonte.

Como funciona em uma frase: você pergunta em português → o sistema busca os trechos mais relevantes nos documentos → um LLM (Gemini) redige a resposta citando as fontes e incluindo disclaimer de não-recomendação.

Exemplo real (validado)

Pergunta: "O que é a CVM?"

Resposta: A CVM (Comissão de Valores Mobiliários) é o regulador do
          mercado de capitais brasileiro [1].
          Isto não constitui recomendação de investimento.

📚 Fontes: docs/teste_cvm.md chunk 0 (vec=0.781, fts=0.194)

2. Arquitetura geral

Visão macro — dois fluxos

FLUXO A — INGESTÃO (offline, roda 1x por lote de docs) docs/*.md data/cvm/ PostgreSQL + pgvector ─────────┐ ─────────┐ ────────────────────── ▼ ▼ ▲ ┌──────────────────────────────────┐ │ │ ingest.py │ INSERT │ │ 1. Lê arquivos (md + cache) │ chunks + │ │ 2. Chunking (1200 / overlap 150)│───embeddings──┘ │ 3. Embeddings gemini-001 (3072d)│ │ 4. Upsert por (source, chunk) │ └──────────────────────────────────┘ FLUXO B — CONSULTA (online, a cada pergunta) Usuário ──► app.py (Chainlit) ──► rag.py │ ┌─────────────────────────┤ ▼ ▼ RETRIEVE (híbrido) LLM (Gemini) ├─ KNN vetorial ├─ recebe trechos + pergunta │ (HNSW halfvec) ├─ responde com citações [n] └─ Full-text (ts_rank) └─ disclaimer obrigatório │ ▲ ▼ │ PostgreSQL trechos como contexto

Detalhe do retrieve híbrido

A busca combina duas técnicas e faz merge dos resultados:

pergunta: "O que é a CVM?" │ ┌────────────┴────────────┐ ▼ ▼ Busca VETORIAL Busca FULL-TEXT embedding da pergunta websearch_to_tsquery (semântica: entende ('portuguese') no sinônimos, contexto) conteúdo (palavras exatas) │ │ ORDER BY embedding ORDER BY ts_rank DESC ::halfvec(3072) <=> LIMIT 4 %s::halfvec(3072) LIMIT 4 │ │ │ └────────────┬────────────┘ ▼ FULL OUTER JOIN USING (id) dedupe por (source, chunk_index) cada hit traz vscore + fscore ▼ TOP_K = 4 trechos
Por que híbrido? A busca vetorial encontra trechos semanticamente parecidos (ex.: "orgão regulador" acha CVM, mesmo sem a palavra). O full-text garante precisão quando o usuário digita termos exatos (ex.: "Resolução CVM 30"). Juntos, cobrem os dois casos.

4. Banco de dados (pgvector)

Schema

CREATE EXTENSION IF NOT EXISTS vector;

CREATE TABLE documents (
  id          SERIAL PRIMARY KEY,
  source      TEXT NOT NULL,          -- ex: docs/teste_cvm.md
  doc_type    TEXT,                   -- ex: regulacao
  title       TEXT,
  chunk_index INT  NOT NULL,
  content     TEXT NOT NULL,
  embedding   VECTOR(3072) NOT NULL,   -- dim do gemini-embedding-001
  UNIQUE (source, chunk_index)        -- chave do upsert
);

-- Índice HNSW: busca aproximada KNN muito rápida
CREATE INDEX ON documents
  USING hnsw ((embedding::halfvec(3072)) vector_cosine_ops);
Por que halfvec(3072)? Um VECTOR(3072) puro consome ~12 KB por linha. O halfvec usa 2 bytes por dimensão (6 KB), cabendo no índice HNSW com performance melhor — e com precisão desprezível perdida.

Busca KNN no Python

# KNN vetorial com halfvec (pgvector)
cur.execute("""
    SELECT id, source, chunk_index, content,
           1 - (embedding::halfvec(3072) <=> %s::halfvec(3072)) AS score
    FROM documents
    ORDER BY embedding::halfvec(3072) <=> %s::halfvec(3072)
    LIMIT %s
""", (query_vec, query_vec, TOP_K))
Workflow SQL: nunca colar SQL direto no bash. Sempre salvar em arquivo com cat > arquivo.sql << 'EOF' e aplicar com psql "$DATABASE_URL" -f arquivo.sql. No psql, usar sempre -P pager=off para não travar no less.

5. Ingestão de documentos

Fluxo detalhado do ingest.py

┌─────────────┐ ┌─────────────┐ │ docs/*.md │ │ data/cvm/ │ fontes locais + cache └──────┬──────┘ └──────┬──────┘ └───────┬─────────┘ ▼ ┌───────────────────────────────┐ │ 1. CHUNKING │ │ RecursiveCharacterTextSplitter│ │ tamanho 1200 / overlap 150 │ └──────────────┬────────────────┘ ▼ ┌───────────────────────────────┐ │ 2. EMBEDDING │ │ gemini-embedding-001 (3072d) │ │ batches de 64 (economia/velo.)│ └──────────────┬────────────────┘ ▼ ┌───────────────────────────────┐ │ 3. UPSERT │ │ ON CONFLICT (source,chunk_idx)│ │ → re-rodar é idempotente ✅ │ └───────────────────────────────┘
Idempotente: rodar ingest.py várias vezes não duplica dados — o upsert por (source, chunk_index) atualiza o que já existe.

Como adicionar novos documentos

cp minha_cartilha_cvm.pdf.txt docs/   # texto extraído do PDF
uv run python ingest.py               # re-rodar a ingestão
Corpus real: a URL dados.cvm.gov.br/.../INSTRUMENTOS retornou 404. Enquanto não achamos o endereço novo, use PDFs oficiais baixados manualmente em docs/ como fonte principal.

6. O motor RAG (rag.py)

Estrutura do módulo

┌─────────────────────────── rag.py ───────────────────────────┐ │ │ │ _embed(text) → vetor 3072d da pergunta │ │ _llm() → ChatGoogleGenerativeAI c/ fallback │ │ retrieve(q, k=4) → busca híbrida (vec + fts) │ │ answer(q) → orquestra tudo e formata │ │ │ │ CLI: uv run python rag.py "pergunta" │ └──────────────────────────────────────────────────────────────┘

Cadeia de fallback do LLM

pergunta chega │ ▼ CHAT_MODEL (do .env) │ falhou (404/503)? ▼ fallback 1 ──► fallback 2 ──► ... ──► raise │ ▼ (sucesso) resposta com citações [n] + disclaimer de não-recomendação

Prompt do synthesizer (regras)

O LLM recebe as instruções:
  1. Responder somente com base nos trechos fornecidos
  2. Citar as fontes no formato [n]
  3. Se não houver base nos trechos → dizer que não sabe
  4. Sempre encerrar com o disclaimer de não-recomendação

Formato da resposta

Resposta: A CVM é o regulador do mercado de capitais brasileiro [1].
Isto não constitui recomendação de investimento.

📚 Fontes:
  1. docs/teste_cvm.md chunk 0 (vec=0.781, fts=0.194)
     └─ vec = similaridade cosseno vetorial (0-1, maior = melhor)
     └─ fts = relevância full-text (ts_rank)

8. Erros comuns e soluções

ErroCausaSolução
404 NOT_FOUND no chat gemini-2.0-flash descontinuado CHAT_MODEL=gemini-flash-latest + fallbacks no rag.py
404 no embedding text-embedding-004 descontinuado gemini-embedding-001 (dim 3072)
503 UNAVAILABLE alta demanda no free tier tentar novamente / cadeia de fallback
psycopg.errors.AmbiguousColumn FULL OUTER JOIN USING(id) com colunas duplicadas aliases prefixados (v_*, f_*) + COALESCE no SELECT
LLM retorna [{'type':'text',...}] .content vira lista de blocos join dos campos 'text' quando isinstance(msg, list)
KeyError 'chunk' chave desalinhada entre retrieve() e answer() padronizar 'chunk_index'
Latência de ~1 min healthcheck llm.invoke("ok") + modelo 404 remover healthcheck; corrigir CHAT_MODEL no .env pendente
psql "suspenso" pager (less) intercepta output -P pager=off ou export PAGER=cat
URL CVM 404 dataset movido PDFs oficiais manuais em docs/
